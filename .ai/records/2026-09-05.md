# 2026-09-05 — 사진 대상 정정

## 발견

사진 기능을 구현하던 중 Storage 함수와 도메인 타입이 `Bean`·`beanId` 기준으로
작성된 것을 확인했다. 사용자가 추가하려는 것은 원두 재고 사진이 아니라 집·카페
`Brew` 기록의 사진 3장이다.

기존 DB에는 이미 `public.brews.photos text[]`와 최대 3장 제약이 있었고, 원두에는
사진 기능이 필요하지 않았다.

## 정정

- 사진 도메인을 `BrewPhoto`와 `Brew.photos`로 이동했다.
- 새 저장 경로는 `brew-photos` bucket과
  `{userId}/brews/{brewId}/{photoId}/...`를 사용한다.
- 기록에 썸네일·확대본 6개 nullable 컬럼을 추가하고, 기존 `brews.photos`는
  데이터 손실을 막기 위해 보존한다.
- 이전에 커밋된 잘못된 `beans` 사진 migration은 새 정정 migration에서 제거한다.
- 미커밋 상태였던 `libs/storage.ts`와 테스트는 기록 기준으로 교체했다.

## 검증

- 기록 mapper·Storage·필터 targeted test: 4개 파일, 29개 테스트 통과
- TypeScript 검사 통과
- Supabase migration은 실행하지 않음
