# PLAN.md - 아직 안 끝난 것만 있는 파일

여기 있는 모든 내용은 목적에 맞는 곳으로 옮겨진다.
"오늘 무엇을 했는지"는 `records/`, 규칙은 `CLAUDE.md` 등 주제에 맞는 위치로 옮겨진다.
코드로 기록되는 거라면 주석이나 테스트 케이스로 옮긴다.

`PLAN.md` 파일에 기록되는 건 "할 일", "정하지 않은 것" 두 가지고 그 이유에 대한 내용은 3줄을 넘기지 않는다.

### 이후 백엔드 작업

**데이터**

- [ ] `recipes`는 나중에 (명세 5장)

**사진** — 명세 3.2의 3슬롯. 아직 스키마에도 없다

크기는 정해졌다: **썸네일 400px · 확대본 2000px · 둘 다 WebP.** 200건에 약 175MB.
레이아웃에서 뽑은 계산 근거는 `records/2026-08-29.md`.

- [ ] **원본을 저장하지 않는다.** 넣으면 200건 × 3장 × 4MB = 2.4GB로 무료 1GB를 바로 넘는다
- [ ] 두 벌을 **클라이언트에서** 만들어 올린다 — 400px q75(~40KB) · 2000px q80(~250KB).
      Supabase 이미지 변환은 **Pro 전용**이라 URL로 크기를 부르는 방식을 못 쓴다
- [ ] **확대본을 1600px으로 줄이지 않는다** — 봉투에 인쇄된 글자가 사진보다 먼저 무너진다
- [ ] **함정: EXIF 회전.** `createImageBitmap(file, { imageOrientation: "from-image" })`.
      빠뜨리면 아이폰 세로 사진만 누워서 올라가는데, **발견 시점엔 원본을 이미 버린 뒤다**
- [ ] 확대본은 **눌러야 로드한다.** 미리 받아두면 무료 대역폭 5GB가 의미를 갖는다
- [ ] **데이터베이스에는 경로만 저장한다.** 도메인은 코드에서 붙인다.
      전체 주소(`https://xxx.supabase.co/...`)를 저장하면 저장소를 옮길 때 데이터를 전부 고쳐야 한다
- [ ] **저장소 조작은 `libs/storage.ts` 한 곳에만.** 올리기 · 지우기 · 주소 만들기.
      여기만 Supabase 를 알면 나중에 옮길 때 이 파일 하나만 바꾼다

확인 — 봉투 사진을 두 크기로 만들어 40KB · 250KB 근처인지, 2000px에서 **로스터리 이름이 읽히는지**
